## 2026-10-15 — Centered YouTube reference and waveform trimming

- `config.py` defines 8 seconds of context on each side of the URL timestamp. The downloader requests `[max(0, timestamp - 8), timestamp + 8]`; it does not shift an early window forward to invent missing pre-roll. Thus `t=1018` requests 1010–1026 seconds, `t=3` requests 0–11, and absent/zero timestamps request 0–8. A short tail remains short, and status reports the saved duration rather than claiming a full 16 seconds.
- Keep `-f bestaudio` and `--force-keyframes-at-cuts` with yt-dlp's ranged download. Installed yt-dlp otherwise stream-copies the range; FFmpeg's input seek may retain pre-roll. Enabling accurate transcoding avoids starting the later duration trim with an already incorrect offset. The final conversion still caps the requested duration and writes 16 kHz mono PCM16 WAV. No whole-video download was added.
- The Gradio 6.17.3 native waveform editor is enabled on Reference Audio with a 16 kHz edit sample rate. Its crop action emits `change`, not `input`. `on_reference_audio_change()` first clears the previous text/path/prompt, then converts and transcribes the selected audio. Its outputs exclude the waveform to avoid an event loop. Saving and generation use the new selected audio, and the editor's reset control restores the preceding selection.
- Programmatic display updates can arrive as Gradio cache copies. Compare unchanged bytes as well as paths and skip those events to avoid duplicate transcription or replacing manually edited text. Also skip `(None, None)` updates so a failed fetch's existing error message survives. Actual user clearing with an old reference still clears the state. Source, profile load, and edit callbacks share the `reference_audio` concurrency group.

## 2026-10-15 — FP16 model weights on MPS

- `uv sync` created the local `.venv` with native arm64 Python 3.13.15. The resulting `uv.lock` records the dependency graph, including Qwen 0.1.1, Gradio 6.17.3, NumPy 2.5.4, Torch 2.14.1, and pywhispercpp 1.5.1. `uv run --locked` subsequently accepted the environment without changing the lockfile.

### Behavior to preserve

- Gradio gives each callback its own concurrency group. Clearing a prompt when reference audio changes is insufficient: an earlier slow save can finish later and restore the old prompt. `app.py` stores reference path and transcript with the prompt and checks both at generation time; a mismatch uses the current reference directly. Manual transcript edits also clear the cache.
- Fixed output filenames allowed another request to overwrite reference audio. Audio is now unique per request within `tmp/session_<uuid>/`; Gradio's session-state deletion callback removes that session's directory after expiration. Keep files alive while their session may still need them. An abrupt process termination can leave session directories behind; no automatic startup deletion of pre-existing user files is performed.
- pywhispercpp's WAV reader requires 16-bit PCM, so checking only the sample rate missed floating-point WAVs. `transcriber.py` checks format, subtype, rate, and channel count and cleans conversion outputs after transcription or conversion failure.
- Microphone integer audio is scaled by its PCM range, rather than amplified to full scale. Only the `change` event transcribes completed recordings, avoiding duplicate work from simultaneous `stop_recording` and `change` handlers.
- Per-model reentrant locks protect singleton initialization and inference. Qwen inference remains on the configured MPS backend; no alternative GPU backend was added.
- Profiles use format version 1 with CPU tensors and plain containers. Restricted `torch.load(weights_only=True)` rejects executable and legacy pickles. Qwen's `VoiceClonePromptItem` is reconstructed from fields after loading, preserving its reference transcript; the installed Qwen generation path moves CPU tensors to its device. Old profile files remain untouched and require recreation from their original audio. Do not restore an unrestricted loading fallback.
- Profile load/delete rejects path traversal and symlinks. Writes use a temporary file and atomic replacement, so a failed save retains the prior profile. Dropdown selection uses the actual sanitized filename.
